## В каком порядке читать

Чтобы понять проект: концепция, потом журнал решений, потом архитектура.
Концепция объясняет форму, решения — почему у этой формы такие границы,
архитектура — что из этого получилось.

Чтобы что-то менять: AGENTS.md, а затем ADR по той области, которую трогаете.

## Чего здесь нет

Справочники прототипа (REST API, CLI, модуль LLM и валидатор безопасности)
описывали удалённый код, поэтому удалены, а не оставлены вводить в заблуждение.
То же с прежним документом по архитектуре: он описывал воркеры Celery и схему
PostgreSQL, которых больше нет.

Справочника по инструментам нет сознательно. Докстринг инструмента — это его
контракт, и именно его клиент показывает агенту; вторая копия в Markdown
разойдётся с ним за неделю. Текущий список печатает `poetry run task eval`, либо
его можно запросить у подключённого клиента.

## Про язык

Русские версии — концепция, архитектура, конфигурация и план работ. Журнал
решений, упаковка и evals написаны по-английски и не переводятся: это рабочие
документы, живущие рядом с кодом и меняющиеся вместе с ним, а расходящийся
перевод хуже его отсутствия.
