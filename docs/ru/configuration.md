# Конфигурация

Всё читается из окружения под одним префиксом. Файла конфигурации, который надо
искать, нет: развёртывание — это один процесс с одним томом.

*English version: [docs/configuration.md](../configuration.md)*

## Настройки

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ANSIBLE_MCP_DATA_DIR` | `/data` | База, плейбуки, артефакты задач, инвентари |
| `ANSIBLE_MCP_TRANSPORT` | `stdio` | `stdio`, когда процесс запускает клиент; `streamable-http` для порта |
| `ANSIBLE_MCP_HOST` | `127.0.0.1` | Адрес, на котором слушает HTTP-транспорт |
| `ANSIBLE_MCP_PORT` | `8080` | Порт HTTP-транспорта |
| `ANSIBLE_MCP_API_KEY` | нет | Bearer-токен, с которым сверяется каждый HTTP-запрос |
| `ANSIBLE_MCP_MAX_CONCURRENT_TASKS` | `4` | Сколько плейбуков может выполняться одновременно |
| `ANSIBLE_MCP_RUN_TIMEOUT_SECONDS` | нет | Сколько может длиться один прогон до отмены и провала |
| `ANSIBLE_MCP_KEEP_ARTIFACTS_DAYS` | нет | Сколько хранить артефакты завершённого прогона; без значения — вечно |
| `ANSIBLE_MCP_EXTRA_INVENTORY_DIRS` | нет | Дополнительные каталоги, откуда провайдер может читать файлы инвентаря |
| `ANSIBLE_MCP_LOG_LEVEL` | `INFO` | Уровень логирования |

## Две, которые важны

**`ANSIBLE_MCP_API_KEY`.** Обязателен, чтобы отдавать HTTP не на loopback, и
сверяется на каждом запросе за постоянное время. Без него процесс выходит с
кодом 2, а не поднимает эндпоинт, исполняющий плейбуки для всякого, кто до
порта дотянулся (ADR-0012). Привязка к loopback работает без проверки и говорит
об этом в лог: дотянуться до loopback уже значит быть на этой машине.

```bash
openssl rand -hex 32
```

**`ANSIBLE_MCP_RUN_TIMEOUT_SECONDS`.** Если не задан, плейбук может висеть
вечно и всё это время держать слот. У `ansible-runner` своего таймаута нет,
так что это единственное ограничение.

## Что остаётся на диске и на сколько

Завершённый прогон оставляет артефакты в `$ANSIBLE_MCP_DATA_DIR/tasks/<id>/`:
вывод, код выхода и по файлу на каждое событие Ansible. Входы, с которыми он
запускался, удаляются по завершении: задача и так их хранит, а инвентарь может
содержать пароль.

`ANSIBLE_MCP_KEEP_ARTIFACTS_DAYS` удаляет при старте артефакты прогонов старше
указанного числа дней. Без него не удаляется ничего и каталог растёт без
ограничений: три прогона плейбука на сорок задач оставляют около 90 КБ в 150
файлах, то есть число файлов важно не меньше их размера.

Строки задач не удаляются никогда. Это история, они маленькие, и в них лежат
слепки, делающие прогон воспроизводимым, — так что подчищенный прогон всё ещё
читается, просто без вывода.

## Где могут лежать файлы инвентаря

Провайдер, настроенный через `inventory_file`, читает только из
`$ANSIBLE_MCP_DATA_DIR/inventories` и из каталогов, названных в
`ANSIBLE_MCP_EXTRA_INVENTORY_DIRS`. Путь резолвится до проверки, поэтому `..` и
симлинки не выводят за пределы.

Конфигурация провайдера приходит вызовом инструмента, то есть её пишет агент;
без этого ограничения «провайдер» был бы способом прочитать любой файл на
хосте и получить его обратно (ADR-0011).

```bash
ANSIBLE_MCP_EXTRA_INVENTORY_DIRS='["/etc/ansible", "/srv/inventories"]'
```

## Credentials провайдеров

Credentials никогда не входят в конфигурацию провайдера. Конфигурация называет
переменную окружения, из которой их читать, а значение остаётся в окружении
(ADR-0006):

```json
{"plugin_type": "yandex_cloud", "config": {"token_env": "YC_TOKEN", "folder_id": "b1g..."}}
```

Значение, похожее на credential, отвергается при добавлении провайдера, а не
сохраняется молча.

## Примеры

Клиент сам запускает процесс — настраивать нечего:

```bash
ansible-mcp
```

Сервис на хосте, доступный извне:

```bash
ANSIBLE_MCP_TRANSPORT=streamable-http \
ANSIBLE_MCP_HOST=0.0.0.0 \
ANSIBLE_MCP_API_KEY="$(openssl rand -hex 32)" \
ANSIBLE_MCP_DATA_DIR=/var/lib/ansible-mcp \
ANSIBLE_MCP_RUN_TIMEOUT_SECONDS=3600 \
ansible-mcp
```

В контейнере, где первые три уже выставлены:

```bash
docker run -p 8080:8080 -v ./data:/data -e ANSIBLE_MCP_API_KEY=... ansible-mcp
```

При установке из пакета настройки лежат в
`/etc/ansible-mcp/ansible-mcp.env` с правами 640, потому что там ключ. См.
[упаковку](../../packaging/README.md).
